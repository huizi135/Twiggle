Integrate opportunity monitoring with decisions, application history, and reflective learning.

01 / Entry gate and product boundary

Begin when capability review and career reasoning are reliable enough to evaluate one opportunity. Reuse the existing huizi135/swiss-job-tracker rather than duplicate discovery and scraping. Its current API and data format must be inspected during implementation; this plan assumes no unverified contract.

Twiggle owns personal relevance, career reasoning, decisions, and feedback. The tracker remains responsible for discovery and raw monitoring unless an explicit future decision changes that boundary.

Monitoring and application states are different. “Company of interest” does not mean an application exists. Applications and feedback remain private.

03 / Core flow

  1. Import or synchronize a tracker record with a stable external identifier.
  2. Resolve its company identity and preserve the raw job snapshot.
  3. Normalize requirements and flag unknown eligibility facts.
  4. Generate a revision-specific assessment using accepted personal claims.
  5. User records Apply, Investigate, Monitor, or Pass, with optional reasoning.
  6. When applying, link the exact CV version and record the actual submission separately.
  7. Record feedback with its source and specificity; distinguish stated reasons from user or AI hypotheses.
  8. Review the decision and update only the model elements supported by feedback.

04 / Integration contract

Start with versioned JSON import/export. Add an authenticated API or scheduled synchronization only after the minimal contract works. Each import includes source system, external record ID, observed timestamp, source URL, company label, vacancy text or permitted reference, location, and optional publication/closure signals.

  • Use a unique source-system/external-ID key and content hash for idempotency and snapshot creation.
  • Different job IDs or changed URLs may be reposts; keep a proposed match with review rather than auto-merging uncertain jobs.
  • A vanished page is an observation, not definitive proof that a position was filled. Keep unknown and observed-closed distinct.
  • Store the last successful sync cursor and errors; retries do not duplicate applications or snapshots.
  • Define conflict rules: raw tracker fields remain sourced; user notes and application states are not overwritten by imports.
  • Import validation failures go to a reviewable quarantine record with reason; avoid silently dropping malformed jobs.

06 / Feedback reasoning

A rejection with no explanation updates the application outcome. It does not establish inadequate skills. A stated permit restriction updates that opportunity’s feasibility evidence, not the user’s technical capability. A successful interview is evidence of that interaction, not proof that an entire strategy is optimal.

Store “employer stated”, “user interpretation”, and “AI hypothesis” separately. Offer a next experiment when appropriate, but preserve uncertainty. Decision quality should be assessed using the evidence available when the decision was made.

07 / Technical approach

Add Company Intelligence, Opportunity Integration, and Decision Journal modules to the existing application. Use background jobs with bounded retries, idempotency, and visible sync state. Keep snapshots and assessments versioned; opening an assessment after a personal-model revision should show that it may need refresh.

Suggested operations: preview import, commit validated import, get company history, capture job snapshot, assess opportunity, record decision, record application transition, attach feedback, and review proposed model updates. Do not send messages, submit applications, or contact employers automatically in this phase.

09 / Evaluation and exit gate

  • Replay duplicate imports, changed descriptions, company aliases, missing publication dates, and uncertain reposts.
  • Simulate interruption after a snapshot write; retry must not duplicate it.
  • Follow one opportunity from discovery through assessment, recorded application, feedback, and retrospective.
  • Verify the exact submitted CV revision remains available independently of later edits.
  • Verify export covers decisions and snapshots while respecting source retention conditions.
  • Defer outreach automation, automatic applications, inferred hiring forecasts, and replacing the tracker.
Build from real experiences. Keep the evidence, uncertainty, and room to change.
